## T-035 — Déclarer `Option.action` (optionnel, 5 valeurs)

### Objectif

Un nouveau champ optionnel `action` sur une option, à 5 valeurs possibles, pour piloter un badge couleur
dans l'écran (SB3) sur les nœuds où ce vocabulaire est celui du contenu réel.

### Décision clé

Vocabulaire fixé par Thibault le 2026-07-28 : **`ajouter`, `remplacer`, `arreter`, `reduire`,
`maintenir`**. Champ **optionnel** — seuls `prescription` et `insuline` le porteront (SA1/SA2), les 4
autres nœuds n'ont pas ce vocabulaire dans leur contenu (valeurs cibles pour `cible-glycemique`, tiers de
risque pour `statine`, pistes comportementales pour les deux nœuds RHD) et ne doivent jamais le recevoir
de force.

### Lire / Modifier

**Modifier** : `schema/noeud.schema.json`, `src/features/decision/content/node.types.ts`.

### Étapes

1. Dans `schema/noeud.schema.json`, définition `option` : ajoute une propriété `action`, `type: string`,
   `enum: ["ajouter", "remplacer", "arreter", "reduire", "maintenir"]`, **absente de `required`**. Rédige
   une `description` courte qui dit explicitement que ce champ est réservé aux nœuds dont le contenu
   emploie déjà ce vocabulaire — pas un champ à remplir par défaut sur tout nœud futur.
2. Dans `node.types.ts` : ajoute `export type ActionOption = 'ajouter' | 'remplacer' | 'arreter' |
   'reduire' | 'maintenir'` (même emplacement que `RoleOption`), et `action?: ActionOption` sur
   `interface Option` (même style que `role`, mais optionnel — `?:`).
3. Vérifie que la validation Ajv des 6 nœuds existants passe toujours (aucun ne porte `action` pour
   l'instant, donc rien ne doit changer) : `npm test -- content.test.ts` (ou le nom exact du test de
   validation de schéma, cherche-le si besoin).

### Validation

- Auto (bloque le commit) : `npm test` → tout vert (aucune régression, `action` est optionnel) ·
  `npx tsc --noEmit` → 0 erreur · `npm run build` → OK.

### Si bloqué

Rien de bloquant attendu — ajout de type optionnel, sans effet sur l'existant.
