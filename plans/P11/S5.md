## T-109 — `EvidenceBadge` en points

### Objectif

Remplacer le badge textuel plein (« Preuve élevée ») par les trois points de la maquette : c'est ce qui
rend possible la carte d'option en une ligne de S6.

### Décision clé

**La maquette a 3 niveaux, le projet en a 4.** `NiveauPreuve` est une union fermée
`eleve | modere | faible | tres-faible` ; `dotStylesFor` (maquette l.574-576) n'en couvre que 3.
Correspondance retenue, sur 3 points :

| Niveau | Points | Note |
| --- | --- | --- |
| `eleve` | ●●● | maquette |
| `modere` | ●●○ | maquette |
| `faible` | ●○○ | maquette |
| `tres-faible` | ○○○ | **extrapolé** — le 4ᵉ niveau n'existe pas dans la maquette |

Ceci **solde la dette** documentée dans `EvidenceBadge.tsx` l.27-30 et `tokens.css` l.43-44
(`tres-faible` retombait sur le style de `faible`, donc les deux étaient indistinguables).

**Le texte ne disparaît pas, il devient invisible.** Un niveau de preuve est une information clinique :
il reste dans le DOM en `<span className="sr-only">` (à créer dans `global.css` s'il n'existe pas) et
en `title` pour la souris. Des points seuls, sans nom accessible, seraient une régression franche pour
un lecteur d'écran.

### Lire / Modifier

- Modifier : `EvidenceBadge.tsx` · `EvidenceBadge.css` · `src/styles/global.css` (classe `.sr-only`) ·
  créer `EvidenceBadge.test.tsx`.

### Étapes

1. `global.css` : ajouter `.sr-only` (masquage accessible standard : `position: absolute; width: 1px;
   height: 1px; overflow: hidden; clip-path: inset(50%); white-space: nowrap`). Vérifier d'abord qu'elle
   n'existe pas déjà.
2. `EvidenceBadge.tsx` : rendre un `<span className="evidence-badge" title={LABELS[niveau]}>` contenant
   3 `<span className="evidence-badge__dot" data-rempli={…} aria-hidden="true" />` puis
   `<span className="sr-only">{LABELS[niveau]}</span>`. Conserver `LABELS` et la prop telle quelle.
3. `EvidenceBadge.css` : points de 7 px (maquette), `border-radius: 50%`. Rempli →
   `background: var(--c-accent-decision)`. Vide → `background: transparent; border: 1.5px solid` avec
   les deux nuances de la maquette (`oklch(75% 0.06 254)` pour un point vide de `modere`,
   `oklch(80% 0.02 245)` sinon) — ou, plus simple et suffisant, une seule nuance de contour ; **tranche
   pour la version simple** et note-le en commentaire.
4. Supprimer les anciennes règles `--eleve/--modere/--faible/--tres-faible` devenues mortes, et les
   tokens `--c-badge-preuve-*` s'ils ne sont plus référencés nulle part (vérifier par `grep` — ils
   pourraient servir au module Veille : dans ce cas, les **garder**).
5. `EvidenceBadge.test.tsx` — 4 tests : le bon nombre de points remplis pour chacun des 4 niveaux ; le
   libellé textuel est présent dans le DOM ; les points sont `aria-hidden` ; `tres-faible` rend un
   résultat **différent** de `faible` (la dette soldée, verrouillée par un test).

### Validation

- **N0 auto (bloque le commit)** : `npx tsc --noEmit` → succès · `npm test` → aucun échec.
  ⚠ `OptionCard.badge.test.tsx` et `OptionCard.test.tsx` rendent `EvidenceBadge` indirectement :
  vérifier qu'aucune assertion n'y porte sur le **texte** du badge. Si oui → c'est un signal que S6
  devra les reprendre ; **le noter dans le rapport de fin de session**, ne pas modifier ces fichiers ici.
- **N1 visuel auto** : — (le badge n'est visible qu'à travers `OptionCard`, refondue en S6 ; la
  vérification visuelle se fait en S8).
- **N2 humain** : trois points sans le mot « élevée / modérée / faible » suffisent-ils en consultation,
  ou faut-il garder le libellé visible sur la carte ? → à consigner dans `VALIDATION.md`.

### Si bloqué

## T-110 — Icônes SVG dans les composants périphériques

### Objectif

Remplacer les caractères ASCII et les puces manuelles par les icônes du kit, dans les trois composants
qui n'appartiennent ni à `CriteriaForm` (S4) ni à `OptionCard` (S6).

### Décision clé

Chaque remplacement conserve **exactement** le rôle d'accessibilité d'aujourd'hui : les glyphes visés
sont tous déjà dans un `aria-hidden` ou sont des puces purement décoratives. Aucun ne porte
d'information seul — sinon le remplacer changerait ce que lit un lecteur d'écran.

### Lire / Modifier

- Modifier : `ArgumentPanel.tsx` (l.80-95) + `ArgumentPanel.css` · `AlertList.tsx` + `AlertList.css` ·
  `CadrageList.css`.

### Étapes

   `<Icon nom="triangle-alerte" />`. Le `<span aria-hidden>` qui l'enveloppe reste.

   (`.argument-panel__list-item::before`), pas une icône : une puce de liste n'est pas un pictogramme.
3. `AlertList.tsx` : ajouter une icône en tête de chaque item, pilotée par le niveau déjà calculé
   (l.41-43) — `triangle-alerte` pour `attention`, `info` pour `info`. `aria-hidden`, le texte de
   l'alerte porte déjà tout le sens.
4. `AlertList.css` : l'item passe en `display: flex; gap` avec l'icône alignée en haut
   (`align-items: flex-start`) — une alerte tient souvent sur plusieurs lignes.
5. `CadrageList.css` : **ne pas ajouter d'icône** (D24, cf. Hors périmètre). Seule retouche autorisée :
   aligner le `<summary>` sur le registre typographique de S1 si l'échelle le permet.

- **N1 visuel auto** : nœud `insuline`, qui déclenche plusieurs alertes de nœud — les icônes
