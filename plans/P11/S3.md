## T-105 — Composant `PastilleInfo`

### Objectif

Fournir la primitive qui rend possible la carte en une ligne (S6) **sans** perdre l'accès tactile aux
contre-indications : un bouton-icône qui montre son contenu **au survol sur un pointeur fin**, et
**au clic sur tous les supports**.

### Décision clé

**C'est l'arbitrage référent du 2026-08-01, question 1** : la maquette met tout en `title=` (survol
seul) ; le code documentait l'inverse (A5 : « un survol est inutilisable au doigt en consultation »).
Retenu : **les deux**, avec le survol en surcouche facultative et le clic comme chemin garanti.

Trois points de conception qui ne se devinent pas :

1. **La bascule se fait sur `@media (hover: hover) and (pointer: fine)`, PAS sur une largeur.**
   L'arbitrage dit « desktop », mais la largeur est le mauvais proxy : un portable tactile large
   afficherait alors une info-bulle qu'aucun doigt ne peut déclencher — exactement le défaut qu'A5
   voulait éviter. La requête média de capacité exprime l'intention réelle. **Le clic fonctionne dans
   les deux branches**, sans exception.
2. **Composant CONTRÔLÉ.** Le contenu déplié doit pouvoir s'afficher ailleurs que sous le bouton — dans
   `OptionCard` il ira sous la rangée entière, pas dans la colonne d'icônes. `PastilleInfo` rend donc
   **le bouton et l'info-bulle seulement** ; le parent détient l'état et rend le panneau. Un composant
   auto-géré rendrait la carte une ligne de S6 impossible à mettre en page.
3. **L'info-bulle n'est jamais l'unique porteuse de l'information.** Elle est `aria-hidden` : le texte
   est déjà accessible par le panneau que le bouton ouvre (`aria-expanded` + `aria-controls`). Sans
   ça, on remplacerait un `title=` par un piège équivalent pour les lecteurs d'écran.

### Lire / Modifier

- Créer : `src/features/shared/ui/PastilleInfo.tsx` · `PastilleInfo.css` · `PastilleInfo.test.tsx`.

### Étapes

1. Props :
   ```ts
   interface PastilleInfoProps {
     icone: NomIcone
     /** Nom accessible du bouton (« Contre-indications », « Posologie »…) — jamais décoratif. */
     libelle: string
     /** Texte montré au survol ET dans le panneau du parent. */
     texte: string
     /** État détenu par le PARENT (cf. Décision clé n° 2). */
     ouvert: boolean
     onToggle: () => void
     /** id du panneau rendu par le parent — câble `aria-controls`. */
     panneauId: string
     /** Registre visuel : `neutre` par défaut, `danger` pour une contre-indication active. */
     ton?: 'neutre' | 'danger'
   }
   ```
2. Rendu : un `<button type="button">` portant `aria-label={libelle}`, `aria-expanded={ouvert}`,
   `aria-controls={panneauId}`, contenant `<Icon nom={icone} />`, suivi d'un
   `<span className="pastille-info__bulle" aria-hidden="true">{texte}</span>`.
3. CSS — l'info-bulle est **masquée par défaut** (`display: none`) et n'apparaît que dans :
   ```css
   @media (hover: hover) and (pointer: fine) {
     .pastille-info:hover .pastille-info__bulle,
     .pastille-info:focus-visible .pastille-info__bulle { display: block; }
   }
   ```
   Positionnement en `position: absolute` sur un parent `position: relative`, `max-width: 280px`,
   `z-index` au-dessus des cartes, couleurs via les tokens de S1. **Prévoir le débordement à droite** :
   la colonne des recommandations est étroite (`minmax(380px, 1fr)`), une bulle ancrée à gauche du
   bouton sortirait de l'écran — l'ancrer à droite (`right: 0`).
4. Ton `danger` → `--c-ton-danger-text` sur l'icône ; `neutre` → `--c-text-faible`.
5. Tests (6) :
   - le bouton porte `aria-label`, `aria-expanded="false"`, `aria-controls` ;
   - un clic appelle `onToggle` une fois ;
   - `ouvert: true` → `aria-expanded="true"` ;
   - l'info-bulle porte `aria-hidden="true"` (le texte n'est **pas** exposé deux fois) ;
   - le texte est présent dans le DOM quel que soit `ouvert` (c'est le CSS qui le masque, pas le JSX —
     sinon aucune info-bulle au survol) ;
   - `ton="danger"` ajoute la classe de registre attendue.

### Si bloqué

Si le positionnement de l'info-bulle demande de mesurer le viewport en JS (`getBoundingClientRect` +
recalage) pour éviter le débordement → **STOP**. Un positionnement purement CSS ancré à droite doit
suffire pour une colonne de largeur connue ; basculer en JS est un changement de nature du composant
(et de son coût de test) qui mérite d'être arbitré, pas décidé en cours de route.
