## T-102 — Compléter les tokens : espacement, typographie, tons sémantiques

### Objectif

Ajouter à `tokens.css` les trois familles qui manquent et que S4→S7 vont consommer : une échelle
d'espacement, une échelle typographique, et les **tons sémantiques** (vert / ambre / rouge / neutre)
qui portent l'arbitrage « couleur des champs de saisie par gravité clinique ».

### Décision clé

**La palette de la maquette est déjà dans le repo à 80 %** — vérifié avant cadrage, ne la réinvente pas :

| Ton de la maquette | Valeurs | Correspondance existante |
| --- | --- | --- |
| orange `border/bg/text` | `oklch(76% 0.12 85)` / `oklch(97% 0.035 85)` / `oklch(48% 0.09 85)` | **identique** à `--c-attention-border` / `--c-attention-soft` / `--c-attention` |
| vert (pastille objectif) | `oklch(55% 0.15 145)` | **identique** à `--c-action-ajouter` |
| rouge (pastille objectif) | `oklch(55% 0.18 25)` | **identique** à `--c-action-arreter` |
| bleu (pastille objectif) | `oklch(46% 0.09 254)` | **identique** à `--c-accent-decision` |
| vert `border/bg/text` | `oklch(70% 0.13 145)` / `oklch(93% 0.05 145)` / `oklch(30% 0.1 145)` | **nouveau** |
| rouge `border/bg/text` | `oklch(76% 0.14 25)` / `oklch(93% 0.06 25)` / `oklch(38% 0.14 25)` | **nouveau** |
| gris `border/bg/text` | `oklch(80% 0.01 245)` / `oklch(94% 0.006 240)` / `oklch(40% 0.02 245)` | **nouveau** |

Le ton ambre **doit aliaser `--c-attention-*`**, pas dupliquer les valeurs : `--c-attention` porte déjà
un sens (« à confirmer ») et deux jeux de variables sur la même couleur divergeraient au premier
ajustement.

### Lire / Modifier

- Modifier : `src/styles/tokens.css` (ajouts en fin de `:root`, avec un commentaire de section par
  famille, dans le style rédigé des commentaires existants du fichier).

### Étapes

1. **Échelle d'espacement** `--space-1` … `--space-8`. Dériver des valeurs réellement employées dans le
   repo (relève rapide : 4, 6, 8, 10, 12, 14, 16, 20, 24, 32 px). Retenir une échelle de 8 crans et
   documenter en commentaire que les composants migreront progressivement.
2. **Échelle typographique** `--text-xs` … `--text-2xl`. Couvrir au minimum les 6 tailles dominantes
   relevées : 11, 12, 13, 14, 15, 17 px. Ajouter `--leading-normal` et `--leading-relaxed`.
3. **Tons sémantiques** : pour chacun des 4 tons `neutre` / `succes` / `attention` / `danger`, trois
   variables `--c-ton-<nom>-border`, `-bg`, `-text`, valeurs du tableau ci-dessus. `attention` aliase
   les `--c-attention-*` existants (`var(--c-attention-border)` etc.).
4. **Pastilles d'état** : `--c-pastille-succes`, `--c-pastille-attention`, `--c-pastille-danger`,
   `--c-pastille-info` — les 4 couleurs pleines des puces de la maquette (l.116-119). Trois des quatre
   aliasent des tokens existants (cf. tableau) ; seule l'ambre `oklch(70% 0.16 85)` est nouvelle.
5. **Combler la dette « preuve très faible »** signalée en commentaire de `tokens.css` l.43-44 :
   ajouter `--c-badge-preuve-tres-faible-bg` / `-text`. Prolonger la progression des 3 niveaux
   existants (le niveau `faible` est `oklch(90% 0.03 254)` sur texte foncé).
6. **Documenter les breakpoints** en commentaire en tête de fichier : les 3 seuils réellement utilisés
   (480, 640, 960) et le fait qu'ils ne peuvent pas être des custom properties (une `var()` est
   interdite dans une `@media`), donc qu'ils restent écrits en dur mais **ne prennent aucune autre
   valeur**. Ne modifier aucune `@media` existante dans cette tâche.

## T-103 — Réparer trois références de variables inexistantes

### Objectif

`.decision-node__repli`, `__repli-resume` et `__repli-mention` sont **hors du système de couleurs
OKLCH** depuis leur écriture : elles référencent trois variables qui n'existent pas et tombent
systématiquement sur des fallbacks hexadécimaux.

### Décision clé

Les tokens du projet sont **tous préfixés `--c-`**. Les trois références fautives —
`var(--border, #d8dce3)`, `var(--text, #1a202c)`, `var(--text-muted, #4a5568)` — ne correspondent à
aucune déclaration de `tokens.css`. C'est un bug silencieux, pas un choix : les couleurs affichées
sont les hexadécimaux de secours.

### Lire / Modifier

- Modifier : `src/features/decision/screens/DecisionNodeScreen.css`, **l.455-480 uniquement**.

### Étapes

1. Repérer les occurrences exactes dans le bloc (l.463, 469, 474, 479 d'après la relève ; **revérifier
   les numéros**, ils ont pu bouger).
2. Remplacer : `--border` → `--c-border` · `--text` → `--c-text` · `--text-muted` → `--c-text-muted`.
   **Supprimer les fallbacks hexadécimaux** : un fallback sur un token qui existe masque la prochaine
   faute de frappe.
3. Ces mêmes règles sont les seules du fichier en `rem` (`1.25rem`, `0.875rem`) : les passer en `px`
   pour rester homogène avec les 480 autres lignes du fichier.
4. Vérifier qu'aucune autre référence sans préfixe `--c-` ne subsiste **dans tout `src/`** :
   `grep -rn "var(--\(border\|text\|text-muted\)[,)]" src/` doit ne rien retourner.

### Validation

- **N0 auto (bloque le commit)** : `npm run build` → succès · le `grep` de l'étape 4 → aucun résultat.
- **N1 visuel auto** : — (vérifié en S8 avec le reste ; le bloc « Autres pistes possibles » n'apparaît
  que sur un profil à plus de 5 options, difficile à provoquer isolément).
- **N2 humain** : —

### Si bloqué
