## T1 — Déclarer `.claude/n0.json`

### Objectif
Créer `.claude/n0.json` avec les commandes typecheck, build et tests du projet, plus la forme ciblée
d'un test ; constater N0 vert.

### Pourquoi
`n0.mjs` sort aujourd'hui en code 2 (« déclarer les commandes dans .claude/n0.json ») : aucune
session de P16 ne pourrait passer sa porte de commit. C'est le préalable de tout le plan (§14.4,
ordre 0).

### Décision clé
Le script ne devine jamais les commandes : il lit un tableau `commandes` (`nom`, `cmd`, `delaiMs`
optionnel) et une clé `testCible` contenant `{fichier}` (`n0.mjs` l.19-21, 64-69). Pas de clé
`perimetre`. Ordre voulu : `typecheck`, `build`, `tests` — noms courts, réutilisés par
`--seulement <nom>` dans les sessions suivantes.

### Lire / Modifier
- Créer : `.claude/n0.json` (nouveau fichier).

### Étapes
1. Créer `.claude/n0.json` :
   `{"commandes":[{"nom":"typecheck","cmd":"npm run typecheck"},{"nom":"build","cmd":"npm run build"},{"nom":"tests","cmd":"npm test"}],"testCible":"npx vitest run {fichier}"}`
   — jamais `npx tsc --noEmit` (compile 0 fichier, `CLAUDE.md` l.26-28).
2. Lancer `node .claude/workflow/bin/n0.mjs` au premier plan (la suite de tests prend ~4 min,
   mesuré le 2026-09-24 : 1 325 tests).
3. Lancer `node .claude/workflow/bin/n0.mjs --cible src/features/decision/engine/<un fichier .test.ts existant>`
   pour constater que `testCible` fonctionne.

### Validation
