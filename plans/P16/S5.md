## T7 — `identite.mjs` et ses tests

### Objectif
Écrire `.claude/skills/recherche-source-primaire/scripts/identite.mjs` : pour un DOI ou un PMID, les
identifiants recoupés, l'accès ouvert légal, rétractation ou correction, les publications du même
essai, le préprint lié — daté, en Markdown ou en JSON ; avec ses tests sur réponses enregistrées.

### Pourquoi
Six accès sur dix déclarés fermés étaient ouverts, six PMID d'OE sur sept étaient faux (§13.3) : un
agent tranchait au jugement ce qu'une API établit. Ce script sert les agents (S8) et le socle (S6) ;
la mesure finale (S10) dira si le remplacer du jugement par l'appel a réduit ces erreurs.

### Décision clé
- **Sources** (toutes sondées depuis ce poste le 2026-09-24) :
  - identifiants — idconv PMC (`pmc.ncbi.nlm.nih.gov/tools/idconv/api/v1/articles/?ids=…&format=json`,
    avec `tool=ebm-msp&email=ebmmsp@gmail.com`), E-utilities (`esearch`/`esummary`/`efetch`,
    PubMed), Europe PMC (`/europepmc/webservices/rest/search?query=DOI:…&format=json`) ;
  - accès ouvert — Unpaywall (`api.unpaywall.org/v2/<DOI>?email=ebmmsp@gmail.com`, adresse arbitrée
    D65) : `oa_status`, meilleure copie, type d'hôte, version, licence ;
  - rétractation, correction — Crossref (`api.crossref.org/works?filter=updates:<DOI>`) : garder les
    avis dont `update-to[].DOI` égale le DOI (casse ignorée), avec type, source
    (`publisher` / `retraction-watch`) et date ;
  - famille d'essai — numéro de registre lu dans la notice PubMed, puis `esearch <NCT>[si]` ;
  - préprint ↔ publication — Europe PMC. Lien **non éprouvé** (§13.2) : le sonder d'abord ; s'il
    n'existe pas, le script écrit `préprint : non vérifiable par API`, jamais « aucun ».
- **Jamais « inaccessible »** : le script rapporte des faits (voie ouverte trouvée, ou aucune connue
  d'Unpaywall et pas de PMCID) et au plus l'état « accès restant à vérifier ». Le vocabulaire des
  états vit dans `acces-identite.md` (S6).
- **Échouer bruyamment** (§14.2) : « non trouvé » est un résultat (voie fermée) ; une réponse de
  forme inattendue (champ attendu absent, statut HTTP inattendu) est une **erreur** qui nomme l'API
  et le champ, code de sortie non nul. Distinguer les deux dans les tests.
- `fetch` injectable (paramètre) : les tests Vitest passent des réponses enregistrées, jamais le réseau.
- Une sous-commande `--sonde-contrat` interroge en direct trois identifiants de référence et vérifie
  la forme des réponses — hors N0 (réseau), à lancer quand une API est suspecte.

  `.claude/skills/recherche-source-primaire/scripts/fixtures/` (réponses d'API enregistrées —

### Étapes
1. Sonder le lien préprint ↔ publication d'Europe PMC sur une paire connue ; décider de l'implémenter

2. Enregistrer en fixtures les réponses réelles pour : un DOI en accès ouvert chez l'éditeur mais
   absent de PMC (ex. sondé : `10.1056/NEJMoa1504720`, Unpaywall `bronze`, idconv sans PMCID) ; un DOI
   rétracté (ex. `10.1016/S0140-6736(20)31180-6`) ; un PMID avec numéro NCT ; une réponse amputée
   d'un champ attendu (fabriquée, pour le test d'échec). Vérifier qu'aucun n'est une signature du
   corpus.
3. Écrire `identite.mjs` : normalisation de l'identifiant, appels, recoupement (identifiants

4. Tests : accès ouvert hors PMC → pas « fermé » ; rétractation détectée avec sa source ; famille
   d'essai listée ; PMID → DOI ; divergence d'identifiants signalée ; champ absent → erreur nommée ;
   erreur réseau → code non nul.
5. Lancer une fois `node .claude/skills/recherche-source-primaire/scripts/identite.mjs --sonde-contrat`
   au premier plan ; résultat dans le bilan.

## T8 — `verifier-registre.mjs` et format du registre

### Objectif
Fixer le format du registre des affirmations (section « Format » de
`references/registre-affirmations.md`) et écrire `scripts/verifier-registre.mjs`, qui refuse un
registre incomplet ; avec ses tests.

### Pourquoi
L'erreur la plus fréquente n'est pas la référence inventée mais la référence réelle qui ne soutient
pas la phrase (§13.2, trois cas dans le dépôt). Relier chaque affirmation au passage lu (P1) n'est
tenu que si une porte le vérifie : le script en fait une porte, pas une intention (§14.2).

### Décision clé
- **Format** : un tableau Markdown à en-tête fixe, une ligne par affirmation, dans le dossier du
  chantier ; il **complète** la table maîtresse (une ligne par étude) et y renvoie par identifiant
  d'étude. Colonnes (P1) : `ID · Sous-question · Affirmation (formulation exacte) · Étude (DOI ou
  PMID vérifié, version) · Localisation (page, tableau, §) · Accès (état) · Donnée extraite · Calcul ·
  Vérification · Contradiction · Destination`.
- **Règles vérifiées** :
  - une ligne `Vérification = vérifiée` a une Localisation non vide et un Accès qui n'est ni
    `non récupéré`, ni `échec technique`, ni `accès restant à vérifier`, ni
    `paywall constaté sur cette voie` ;
  - toute ligne qui mentionne un NNT a un Calcul qui commence par `publié`, `recalculé :` (suivi des
    données d'entrée : risques des deux bras, horizon) ou `non calculable :` (suivi du motif) ;
  - un NNT `recalculé` dont les entrées sont chiffrées est recalculé par le script (1 / différence
    de risque absolu, arrondi supérieur) et comparé au NNT écrit ;
  - valeurs de Vérification admises : `vérifiée`, `non vérifiée`, `non vérifiable`, `contredite`.
- **Format imposé aux nouveaux dossiers seulement** (§14.2) : aucun dossier existant n'est converti.
- Le **domicile** du format est la section « Format (contrat de verifier-registre.mjs) » de
  `registre-affirmations.md`, créée ici ; S6 écrit la marche à suivre dans le même fichier, sans
  toucher cette section.

### Lire / Modifier
- Créer (nouveaux fichiers) : `.claude/skills/recherche-source-primaire/scripts/verifier-registre.mjs`,
  `.claude/skills/recherche-source-primaire/scripts/verifier-registre.test.mjs`,
  `.claude/skills/recherche-source-primaire/references/registre-affirmations.md` (section Format
  seulement, avec un exemple de tableau valide).

### Étapes
1. Écrire la section « Format » : colonnes, valeurs admises, syntaxe du Calcul, un exemple valide
   (données fictives marquées comme telles).
2. Écrire `verifier-registre.mjs <fichier.md> [--json]` : lecture du tableau, contrôle de l'en-tête,
   règles ci-dessus, erreurs avec numéro de ligne, code 1 si au moins une erreur.
3. Tests : registre valide accepté ; `vérifiée` sans localisation refusé (ligne citée) ; NNT sans
   statut refusé ; NNT recalculé incohérent refusé ; `non calculable : <motif>` accepté ; en-tête
   modifié refusé.

### Validation

- **Tests** : `verifier-registre.test.mjs`, cas de l'étape 3.

- **N2 humain** : —
