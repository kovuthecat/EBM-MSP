## T22 — Jouer les huit épreuves de §11.5

### Objectif
Jouer les huit épreuves de `cas-module/`, avec la skill en configuration 3 (commit courant), puis les
corriger, appliquer la règle de verdict et écrire le rapport d'épreuves.

### Pourquoi
La skill orchestre un procédé dont les erreurs coûtent cher : un contenu clinique produit sans le
référent, une porte franchie, une validation écrasée à la reprise. Les épreuves de §11.5 vérifient
qu'elle aiguille, s'arrête et reprend au bon endroit **avant** qu'un vrai deuxième domaine s'ouvre
avec elle. C'est la porte de l'étape 7 de §14.4.

### Décision clé
- Harnais : `lancer.mjs canari --corpus cas-module`, puis
  `mesurer --corpus cas-module --config 3 --commit <HEAD>` ; `attendre` au premier plan jusqu'à
  « lot terminé ». Rien ne tourne après la réponse finale.
- Même règle de verdict que le corpus de recherche : 2 exécutions, 3e si le résultat est partagé
  (1/2), exécution invalidée rejouée.
- **Porte** : les huit épreuves réussies. Une épreuve échouée → `FAIL`, avec l'épreuve, ses
  exécutions et leurs `grading.json`, pour la remédiation.
- Livrable, lisible sans la conversation : `mesures/<date>-module/rapport.md`, avec :
  - le verdict par épreuve ;
  - ce que la skill a fait à chaque porte (d'après la transcription) ;
  - les exécutions invalidées ;
  - le coût.

### Lire / Modifier
- Créer : `docs/commun/epreuves-recherche/mesures/<date>-module/` (enregistrements, `resultats.json`,
  `rapport.md`).

### Étapes
1. Lancer le canari sur le second corpus, qui doit sortir vert.
2. Lancer le lot, puis attendre au premier plan.
3. Un correcteur par épreuve, au premier plan (`grading.json`).
4. 3e exécution pour les résultats partagés ; rejouer les exécutions invalidées.
5. Rapport. Les items N2 des vagues verrouillées (S2, S3, S10, S11) sont reversés par la vague de
   clôture, pas ici.

### Validation
- **N0 auto (bloque le commit)** : `node .claude/workflow/bin/n0.mjs` → exit 0.
- **Tests** : — (mesure : verdicts calculés par `verdicts.mjs`, testé en S4).
- **N1 visuel auto** : —
- **N2 humain** : le référent lit le rapport d'épreuves. Pour chaque épreuve, le comportement
  constaté est-il celui qu'il attend d'un assistant de cadrage ? Non bloquant → `VALIDATION.md`.
- **Anti-raccourci** : l'épreuve « référent absent » peut réussir parce que la skill s'arrête dès le
  premier message, pour une autre raison, par exemple un fichier introuvable dans l'export. Le
  correcteur lit **pourquoi** elle s'arrête dans la transcription. Un arrêt pour erreur technique
  compte comme exécution invalide, pas comme réussite.

### Si bloqué
Canari rouge sur le second corpus : `FAIL` nature `environnement` si la liste blanche de
`cas-module/README.md` cite un chemin absent, qui se corrige par un correctif localisé signalé. Sinon
`FAIL` nature `prémisse`, écrite falsifiable.
