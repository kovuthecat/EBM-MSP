## T5 — Harnais `claude -p` isolé, canari et verdicts

### Objectif
Écrire sous `docs/commun/epreuves-recherche/harnais/` un harnais Node qui exécute chaque épreuve dans
un export isolé par `claude -p`, prouve son isolement par un canari, invalide les exécutions
contaminées et calcule les verdicts ; avec ses tests Vitest.

### Pourquoi
Les rapports correcteurs sont dans le dépôt, et le dépôt est public : un exécutant qui peut les lire
« réussit » sans raisonner, et la mesure surestime les skills actuelles (constat du critique, sondé le
2026-09-24 : un `claude -p` lancé hors du dépôt lit quand même le dépôt par chemin absolu). Le
harnais est ce qui rend les mesures de S4, S10 et S12 aveugles et comparables. Il est aussi le seul
garant, dans les épreuves, qu'aucune requête OE ne part (pas de hook, arbitrage du 2026-09-24).

### Décision clé
- **Une exécution = un `claude -p` dans un export neuf** (jamais réutilisé entre deux exécutions : la
  deuxième lirait la sortie de la première). Export = `git archive <commit>` des seuls chemins de la
  liste blanche du README, moins les exclusions du cas, plus `epreuve/entrees/` (pièces du cas) et
  `epreuve/sortie/` (vide). Emplacement : sous `os.tmpdir()`, jamais dans le dépôt.
- **Réglages de l'export** (`.claude/settings.json` écrit par le harnais, lancé avec
  `--setting-sources project` pour que les réglages utilisateur ne s'appliquent pas) :
  - refus : `Read(//c/Users/Kovu/Projets/ebm-msp/**)` (forme sondée le 2026-09-24 : bloque Read
    **et** Grep), `Read(//c/Users/Kovu/Projets/Interface-OE/**)`, `WebFetch(domain:github.com)`,
    `WebFetch(domain:raw.githubusercontent.com)`, `PowerShell` ;
  - autorisé : Read/Grep/Glob/Write/Edit dans l'export, WebFetch, WebSearch, Skill, Agent ; `Bash`
    **seulement** pour `node .claude/skills/recherche-source-primaire/scripts/*` quand ces scripts
    existent au commit mesuré (configuration 1 : aucun Bash) ;
  - mode de permission qui **refuse** tout ce qui n'est pas pré-autorisé (nom exact lu dans
    `claude --help` ; attendu : `dontAsk`) ;
  - modèle : `--model sonnet` et `env.CLAUDE_CODE_SUBAGENT_MODEL = "sonnet"` — même modèle dans les
    trois configurations (constat 4 du critique).
- **Chemin du CLI OE neutralisé** dans les fichiers texte de l'export (toute occurrence de
  `Interface-OE/out/cli/index.js` → `CHEMIN-OE-NEUTRALISE/index.js`) : double garde avec le refus de
  Bash.
- **Export contaminé = refusé** : si une signature du cas figure dans un fichier texte de l'export, le
  harnais refuse de lancer (erreur explicite, cas nommé).
- **Canari** (`lancer.mjs canari`, modèle `haiku` pour le coût) : un export sans cas, une consigne qui
  tente dix gestes. Attendu : **refusés** — Read, Grep et Glob sur le dépôt, Bash `echo`, PowerShell,
  WebFetch `https://github.com/kovuthecat/EBM-MSP`, Read dans `Interface-OE/`, et un **sous-agent**
  (outil Agent) qui tente le même Read du dépôt ; **réussis** — Read de `CLAUDE.md` dans l'export,
  WebFetch `https://pubmed.ncbi.nlm.nih.gov/`. Le verdict se lit dans la transcription (résultats
  d'outils en erreur, `permission_denials`), jamais dans la réponse du modèle. Canari rouge → `mesurer`
  refuse de tourner.
- **Invalidation** d'une exécution, d'après sa transcription `stream-json` : toute tentative d'outil
  vers un chemin du dépôt ou d'`Interface-OE`, toute URL `github.com/kovuthecat` dans une entrée ou
  un résultat d'outil. Invalidée = rejouée, ne compte pas.
- **Correction** : un correcteur (sous-agent `general-purpose`, Sonnet, au premier plan) par cas,
  pour ses exécutions ; il lit le livrable et les assertions R* du cas, écrit `grading.json` au format
  skill-creator. Assertion vérifiable par script → script, pas jugement. **Exécution réussie = toutes
  ses assertions passées.**
- **Verdicts** (`verdicts.mjs`, fonctions pures) : la règle du README, rien d'autre.
- **Lots longs sans arrière-plan orphelin** : `lancer.mjs mesurer` démarre le lot (concurrence 2,
  délai 30 min par exécution, une reprise sur erreur technique ou limite de débit) et rend la main ;
  `lancer.mjs attendre --max 540` s'appelle au premier plan, en boucle, jusqu'à « lot terminé ». La
  session ne rend jamais sa réponse finale avec un lot en cours.
