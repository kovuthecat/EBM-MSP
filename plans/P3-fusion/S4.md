# S4 · T‑023 — Vérification d'encodage bi‑agents (A fidélité + B red‑team moteur)

**Modèle/effort** : Opus · xhigh — **exécutée via l'outil `Workflow`** (multi‑agents).
**Dépend de** : S3. **Sortie** : `docs/decision/validation/prescription-encodage-biagents.md`.
**C'est la re‑validation qu'impose la fusion.**

## But

Prouver que le YAML fusionné est (A) **fidèle** au dossier S2 et à la spec S1, et (B) **robuste** face à un
adversaire qui exécute le **moteur réel** sur des profils patients. Gate : **0 finding HAUTE**.

## Méthode (reprise du protocole nœuds C/D/E/H)

- **Agent A — fidélité** : chaque option / exclusion / priorité / alerte du YAML correspond à une affirmation
  sourcée du dossier ; aucune valeur inventée ; nuances B/C/D toutes présentes (checklist des « nuances à
  préserver » de l'`index.md`). Signale toute dérive.
- **Agents B — red‑team** (mandat de réfuter ; doute ⇒ « problème ») : construire un **banc de profils** et
  faire tourner `evaluateNode` sur le YAML réel. Cibles prioritaires (les règles **nouvelles**, jamais
  validées) :
  - **Patient fragile / dénutri / IMC bas + comorbidité** : vérifier que GLP‑1 et **tirzépatide** sont
    exclus **ou** rétrogradés **et** alertés — jamais recommandés en tête. (Remarques 3/10/11.)
  - **ASCVD pur (sans IC/rénal)** : GLP‑1 **devant** iSGLT2. (Remarque 9.)
  - **Portes** : SU/gliptine + `en_dessous` → **déprescription** (jamais switch montant) ; SU/gliptine +
    `à la cible`/`au‑dessus` → **switch** ; intolérance → switch selon nature. (Décision référent.)
  - **Sécurité dure** : jamais gliptine+GLP‑1 associés ; jamais retrait d'iSGLT2/GLP‑1 en désintensification ;
    metformine exclue < 30 ; SU exclu < 30 ; iSGLT2 exclu < 20 ; sitagliptine dosing ; glibenclamide absent.
  - **Sorties vides / contradictoires** : chercher un profil où l'outil ne propose rien d'utile, ou propose
    deux options incompatibles simultanément.
- **Triangulation** : tout finding EBM se confirme sur source primaire, jamais OpenEvidence seul.

## Boucle de correction

Chaque finding HAUTE → correction en S3 (YAML) → re‑run S4 jusqu'à **0 HAUTE**. Les findings MOYENNE/BASSE
sont consignés (arbitrage référent en S6). Journaliser corrections + profils tracés.

## Critère de sortie

`prescription-encodage-biagents.md` : banc de profils, verdicts, findings triés, **0 HAUTE résiduelle**,
tous les garde‑fous de sécurité et toutes les règles nouvelles confirmés sur le moteur réel.
