## Contexte (pourquoi cette session existe)

S1 (T-018) a inversé le défaut de détermination des critères `bool`/`liste` (D30) : un critère non
répondu est désormais indéterminé, sauf `presomption_non: true` explicite. Deux critères du nœud
`prescription` — `traitements_en_cours` (liste) et `intolerance_traitement` (bool) — sont masqués par
`visible_si: "intention != initier"` et ne peuvent **pas** recevoir `presomption_non` (ils gardent de
vraies conditions `role: securite` / `exclusions` ailleurs sur ce même nœud). Conséquence réelle,
confirmée par les invariants du banc (I10 `invariants-contenu.test.ts`, I11 `impasse.test.ts`) : pour un
patient `intention == initier` (naïf par construction), une vingtaine d'options qui portent sur un
traitement déjà en cours (arrêter/réduire/remplacer/désintensifier…) partent **en attente** au lieu
d'être proprement **non retenues**, en réclamant un champ que l'écran ne montre même pas à ce patient.

S1 a documenté ce trou sans le corriger (hors périmètre : moteur générique, aucun contenu clinique
au-delà de sa liste mécanique) via deux dettes nommées et auto-expirantes :
`IMPASSES_CONNUES_T018` dans `engine/banc/impasse.test.ts`, `VIOLATIONS_R8_CONNUES_T018` dans
`engine/banc/invariants-contenu.test.ts` — chacune avec les clés
`prescription :: traitements_en_cours` et `prescription :: intolerance_traitement`.

Cette session applique le motif **R8** déjà en place ailleurs dans le même fichier (ex. `mcg_disponible`
sur le nœud `insuline`, cf. `VIOLATIONS_R8_CONNUES_T018` pour un cas où c'est déjà correct) : répéter le
garde de visibilité dans chaque terme `OR` qui lit le critère masqué. Ce n'est pas une nouvelle règle
clinique inventée — c'est l'application mécanique d'un motif déjà validé sur ce projet — mais ça reste une
modification de `content/`, donc soumise à D5 (bump de version + changelog) et à relecture référent avant
que le nœud repasse `valide`.

## T-031 — Répéter le garde `intention != initier` sur `traitements_en_cours` / `intolerance_traitement`

### Objectif

Aucune option de `prescription` ne doit plus partir « en attente » sur ces deux critères pour un patient
`intention == initier`. Les invariants I10 et I11 doivent passer **sans** les entrées
`prescription :: traitements_en_cours` / `prescription :: intolerance_traitement` dans les deux listes de
dette (elles doivent être supprimées, pas contournées).

### Étapes

1. Recense **mécaniquement** (relis l'algorithme d'I10 avant de coder le tien à la main, ou réutilise-le
   en le rejouant en isolation si c'est plus fiable) tous les termes `OR` de `conditions`, `prerequis`,
   `exclusions`, `derive`, et `alertes[].quand` du nœud `prescription` qui citent `traitements_en_cours`
   ou `intolerance_traitement` (mot entier) et qui ne sont **pas déjà protégés** — ni par répétition du
   garde dans le même terme, ni par acquisition via une condition/prérequis non disjonctive de la même
   option qui contraint déjà `intention`.
2. Pour chaque terme non protégé : ajoute `intention != initier AND ` en tête du terme (même idiome que le
   reste du fichier — vérifie l'ordre de précédence AND/OR avant d'insérer, `AND` lie plus fort que `OR`
   dans cette grammaire, donc le préfixe s'applique bien seulement à CE terme).
3. Cas particulier `intolerance_traitement == true` seul (option « Optimiser l'agent mal toléré ») : la
   même règle s'applique, même si le terme ne contient qu'une seule clause.
4. Après modification : fais tourner I10 et I11 sur `prescription`. Ils doivent passer **par la vraie
   protection**, pas par la dette. Retire alors les deux entrées `prescription :: *` de
   `IMPASSES_CONNUES_T018` (`impasse.test.ts`) et de `VIOLATIONS_R8_CONNUES_T018`
   (`invariants-contenu.test.ts`) — les deux tests réclament ce retrait dès que la dette est résorbée
   (auto-expiration), ne les laisse pas traîner.
5. **Bump de version + changelog** dans `prescription.yaml` (D5) : décris le fix comme un correctif
   technique (répétition de garde, motif R8), pas comme une décision clinique nouvelle — et note qu'il a
   été découvert par P4/S1 (T-018).
6. Si un site te semble ambigu — c'est-à-dire que l'ajout du garde changerait le comportement pour un
   patient qui N'EST PAS `initier` (et pas seulement neutraliser le cas `initier`) — **ne tranche pas** :
   liste-le dans ton rapport pour revue référent, laisse la dette en place pour CE site précis
   uniquement, et documente pourquoi dans le fichier.

### Validation

- Auto (bloque le commit) : `npm test` → tout vert (y compris I10/I11 sans les deux entrées de dette
  `prescription`) · `npx tsc --noEmit` → 0 erreur · `npm run build` → OK · validation Ajv du nœud
  `prescription` → OK.
- Auto : rejoue le profil de reproduction (patient `intention == initier`, aucun `traitements_en_cours`
  saisi, aucune `intolerance_traitement` saisie) et vérifie qu'aucune des ~20 options citées dans le

- Humain (bloquant pour `valide`, pas pour le commit) : relecture référent des termes modifiés avant que
  le nœud repasse `valide` — à consigner dans `VALIDATION.md` à la consolidation.
