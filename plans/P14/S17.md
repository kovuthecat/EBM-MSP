## T-190 — Le déplacement, sans changer une virgule de comportement

### Objectif

Que chaque fait de la liste validée soit défini **une fois** dans le fichier commun et **référencé** par
les nœuds, sans que la sortie du moteur bouge d'un profil.

### Décision clé

Le critère de réussite est mesurable et sévère : **aucun snapshot `caracterisation.*` ne doit bouger.**
Un déplacement est une opération de forme ; s'il change une sortie, c'est qu'une définition a changé au
passage — c'est-à-dire exactement le contraire de ce qu'on cherche.

Les deux exceptions attendues, et **elles seules** :

- `terrain_cible_assouplie` — déjà aligné en S8/T-173, donc identique des deux côtés au moment où cette
  session s'exécute : le déplacement est neutre ;
- `cible_atteinte` — déjà unifié en S11/T-180 : idem.

Si un troisième critère fait bouger un snapshot, c'est un défaut, pas un effet de bord.

### Lire / Modifier

- Modifier : `content/decision/criteres-communs/diabete-type-2.yaml`, les 6 YAML de nœuds
- Régénérer (pour contrôle, pas pour acceptation) : les snapshots `caracterisation*` et `paires.*`

### Étapes

1. Pour chaque fait de la liste validée : écrire sa définition **une fois** dans le fichier commun
   (`type`, `valeurs`, `min`/`max`/`paliers`, `derive`, `partage`, `aide`, `concerne`).
2. Dans chaque nœud qui le déclarait, remplacer la déclaration complète par `{ ref: <nom> }` **augmenté
   de sa seule mise en scène** (`groupe`, `visible_si`, `valeurs_visible_si`, `debut_de_ligne`,
   `masque_si_indetermine`, `preremplissage`, `libelle_masque`, `presomption_non`).
3. **Vérifier `presomption_non` un par un** : il reste local, et son éligibilité dépend de l'usage du
   critère **dans ce nœud** (D30). Ne jamais le remonter dans le fichier commun, même quand les deux
   nœuds portent la même valeur — l'invariant S2/T-165 doit rester vert.
4. Renseigner `concerne` pour chaque fait : les classes ou gestes qui le rendent pertinent. **C'est ce
   champ qui arme l'invariant S16** ; le remplir à la légère le rend soit muet, soit bruyant.
5. Relire les nœuds : un critère référencé ne doit plus porter **aucun** champ de définition (le schéma
   de S15 le refuse, mais le vérifier à la lecture évite d'apprendre l'erreur par un test).
6. Mettre à jour `changelog` et `version` de chaque nœud touché.

### Validation

  - `npm test` → vert. **`caracterisation.*` : aucun diff**, sur les 6 nœuds. Un diff = STOP, ne pas
    l'accepter, ne pas régénérer.
  - `npx vitest run src/features/decision/engine/banc/coherence-inter-noeuds.test.ts` → I19/I32 verts
    (ils deviennent partiellement sans objet : un fait déclaré une seule fois ne peut plus diverger —

  - L'invariant S2/T-162 (même nom = même définition) reste vert.
  - `npm run build`, `npm run typecheck` → verts.
- **N1 visuel auto** : les formulaires des 6 nœuds, sur un profil vierge — **aucun champ n'a changé de
  groupe, d'ordre, d'aide ni de visibilité** → `/verif-visuelle`.
- **N2 humain** : le fichier commun relu de bout en bout par le référent (c'est désormais l'autorité du
  vocabulaire du domaine) → `VALIDATION.md`.

### Si bloqué

- Un snapshot qui bouge : **STOP**, toujours. C'est le signal que le déplacement n'était pas neutre.
- Un fait dont les deux définitions divergent et que S14 n'a pas tranché : **STOP**, ne pas choisir.
